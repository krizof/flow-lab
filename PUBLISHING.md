# Публикация обновлений

Новая версия должна быть собрана и проверена разработчиком. Приложение не создаёт обновления само: оно доставляет пользователям опубликованные релизы.

## Через PowerShell (рекомендуется)

Нужны GitHub CLI (`gh`) и вход в аккаунт с правами на `krizof/flow-lab`.

1. Соберите новый EXE. Версия сборки должна совпадать с номером выпуска.
2. Запишите описание изменений в UTF-8 файл, например `notes.txt`.
3. Выполните из папки этого репозитория:

```powershell
.\Publish-Release.ps1 -Exe "C:\build\Discord-Flow-Lab.exe" -Version "0.8.0" -NotesFile "C:\build\notes.txt" -Importance normal
```

Для важного исправления используйте `-Importance important`. Скрипт подготовит дистрибутив, создаст черновик, загрузит файлы, сверит SHA256 GitHub с локальным EXE и только затем опубликует выпуск как Latest. Опубликованные выпуски не перезаписываются: выпускайте следующий номер.

## Вручную через сайт GitHub

1. Releases → Draft a new release.
2. Тег строго вида `v0.8.0`; без prerelease. Версия EXE — `0.8.0.0`.
3. Описание — обычный список изменений. Для важного выпуска добавьте отдельной строкой:

```html
<!-- flow-lab:important -->
```

4. Прикрепите **Flow-Lab.exe** — именно это имя ожидает приложение. Дополнительно ZIP и SHA256SUMS.txt.
5. Сохраните черновик, дождитесь завершения загрузки всех файлов, затем Publish release и Set as latest release.
6. На клиенте нажмите «Проверить Flow Lab» и проверьте версию/описание.

Для автоматической установки GitHub должен вернуть SHA256 (`digest`) EXE через API. При отсутствии хеша приложение откажется от установки, сохранив старую версию. Личные токены не встраиваются в приложение.

Номер должен расти численно: 0.10.0 новее 0.9.9. Draft и prerelease пользователям не предлагаются. Отметка «важное» заметнее в интерфейсе, но не принуждает к установке.

## Перед выпуском

Проверьте модульные, файловые и GUI-тесты, подготовьте понятное описание ограничений. Не добавляйте в дистрибутив пользовательские settings.json, журналы, захваты, локальные секреты Telegram или ключи GitHub. Проверка обновления не гарантирует работоспособность всех сетевых маршрутов.
